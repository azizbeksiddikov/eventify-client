# Internationalization

Languages: English (`en`, default and fallback), Korean (`ko`), Russian (`ru`), Uzbek (`uz`).

## How it works

- Translations are JSON files at `public/locales/<lng>/<namespace>.json`.
- `libs/i18n/provider.tsx` (`I18nProvider`, mounted in `src/app/providers.tsx`) fetches every namespace for the active language in the browser at start, caches them in memory, and initialises `i18next`. Nothing renders until the files are loaded.
- The chosen language is stored in `localStorage` under `locale`; the default is `en`. There is no language detection and no language in the URL.
- Components use `useTranslation("<namespace>")` from `@/libs/i18n`; `useI18n()` gives the current locale and a way to change it.
- The language switcher is in `Header`. `FontProvider` and `libs/fonts.ts` pick a font stack that fits the language (Cyrillic, Korean, Latin).
- Dates use the locale through `Intl` (`libs/eventDates.ts`), so they follow the language automatically.

## Namespaces

| Namespace                        | Covers                                      |
| -------------------------------- | ------------------------------------------- |
| `header`, `footer`               | navigation, language and theme menu, footer |
| `home`                           | home page sections                          |
| `events`, `groups`, `organizers` | list pages, detail pages, forms, filters    |
| `profile`                        | profile tabs, settings, tickets             |
| `auth`                           | login and signup                            |
| `comments`                       | comments                                    |
| `calendar`                       | calendar widget                             |
| `help`                           | FAQ page                                    |
| `admin`                          | admin panel                                 |
| `errors`                         | user-facing error sentences (`err_*` keys)  |

The list that actually loads is `namespaces` in `libs/i18n/provider.tsx`. `next-i18next.config.js` has a similar list; keep the provider list as the source of truth and update both if you add a namespace.

## Adding or changing text

1. Add the key to **all four** `public/locales/{en,ko,ru,uz}/<namespace>.json`. Missing keys fall back to English (`fallbackLng`).
2. Use the key in the component: `t("key")`.
3. Do not hard-code a user-visible sentence in a component, including toasts, `placeholder`, `aria-label` and `title` text. Use translation keys. Do not use an English sentence as a key.
4. Run `npm run check:i18n`.
5. Check the longest language (Russian) in the layout: no overflow at 360 px wide.

## Backend error messages

The backend sends an error **code** with every error (the key of its `Message` enum, for example `EVENT_FULL`) and optional `params`. The code is also the key in `errors.json`, so the client never matches English text. An error with no code, or a code with no text, shows `UNKNOWN_ERROR`, never raw English.

When the backend adds a new user-facing error (a new member in its `Message` enum):

1. Add the code as a key in `public/locales/<lng>/errors.json` for **all four** languages. Use `{{name}}` for values from `params` (the backend sends `params: { name: ... }`).
2. Run `npm run check:i18n -- <path to the backend libs/enums/common.enum.ts>`. It fails for any backend code without a text.

Errors created in the client use `new AppError("CODE")` with a code from the same file.

Show errors with `smallError(friendlyErrorMessage(error))`.

## Checking

`npm run check:i18n` compares every language with English and fails on a missing or extra file or key, an empty value, different `{{placeholders}}`, or an error code used in the app that has no text. Pass the path to the backend's `libs/enums/common.enum.ts` after `--` to also check every backend error code. The first part also runs inside `npm test` (`tests/locales.test.ts`).

## Adding a language

1. Copy `public/locales/en` to `public/locales/<new>` and translate every file.
2. Add the code to the language list in `libs/components/layout/Header.tsx` and to `next-i18next.config.js`.
3. Check fonts in `libs/fonts.ts` cover the script.
4. Check dates and number formatting in that locale.
